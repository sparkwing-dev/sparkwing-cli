CI/CD pipelines in Go

Write your pipelines as real code, not YAML. Get compile-time errors, IDE autocomplete, and the full power of a real programming language for your CI/CD.

sparkwing cluster create --name dev

Why Sparkwing

Code, not config

Your pipelines are Go programs. Real imports, real functions, real error handling. No YAML templating nightmares.

One command setup

sparkwing cluster create gives you a full CI/CD stack in 2 minutes. Controller, listeners, dashboard, git cache — all local.

Content-addressed caching

Same code = same hash = skip. Tests that already passed? Instant. Builds that already ran? Cached. Zero wasted compute.

Structured pipelines

Jobs run sequentially. Parallel() runs jobs concurrently. Breakpoints let you pause and inspect. Timeouts keep things safe.

GitHub native

Push to a branch → status check on your PR. Per-job reporting. Webhook-triggered. Branch enforcement for deploys.

Secure by default

Deploy requirements, signed cache entries, rate limiting, audit logging, API auth. Trust verification before every deploy.

Real Examples

Simple build + deploy

package jobs

import (
    "github.com/koreyGambill/sparks-core/docker"
    "github.com/koreyGambill/sparks-core/deploy"
)

func JobMyapp() {
    docker.BuildAndPush(docker.BuildConfig{
        Image:      "myapp",
        Dockerfile: "Dockerfile",
        Registries: registries,
    })
    deploy.Run(deploy.Config{
        AppName:   "myapp",
        Namespace: "default",
        Images:    []string{"myapp"},
    })
}

Parallel test shards + deploy

func JobMyapp() {
    // Run tests in parallel shards
    sparkwing.SpawnAll("test", []string{"0", "1", "2"},
        sparkwing.SpawnPipeline("myapp-test"),
        sparkwing.WithEnv(func(val string) map[string]string {
            return map[string]string{"SHARD": val}
        }),
    )

    // Lint in parallel via a named step
    sparkwing.RunStep(step.Shell("lint", "golangci-lint run"))

    // Build and push
    docker.BuildAndPush(docker.BuildConfig{
        Image:      "myapp",
        Dockerfile: "Dockerfile",
        Registries: registries,
    })

    // Gate deploy behind approval
    sparkwing.RunStep(step.RequireApproval("deploy-gate"))
    deploy.Run(deploy.Config{
        AppName:   "myapp",
        Namespace: "prod",
        Images:    []string{"myapp"},
    })
}

Dynamic monorepo detection

// Reads SPARKWING_CHANGED_FILES from the webhook
// Only builds apps whose files actually changed
func JobBuildChanged() {
    apps := changedApps()
    sparkwing.SpawnAll("build-changed", apps,
        sparkwing.SpawnPipeline("build-app"),
        sparkwing.WithEnv(func(app string) map[string]string {
            return map[string]string{"APP": app}
        }),
    )
}
